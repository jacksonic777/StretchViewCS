# Delphi → Visual C# 変換可能性分析レポート

## 概要
StretchViewは、Windows用のデスクトップキャプチャ・画像表示アプリケーションです。このレポートでは、DelphiからVisual C#への変換可能性を詳細に分析します。

## 変換可能性評価：**可能（中〜高難度）**

- **難易度**: 中〜高
- **推定作業時間**: 2〜4週間（経験豊富な開発者の場合）

### 2.2 ⚠️ 変換可能だが注意が必要

#### 2.2.1 Windows API呼び出し
**使用されている主なAPI:**
- `BitBlt`, `StretchBlt` - 画像コピー
- `GetWindowDC`, `GetDC` - デバイスコンテキスト取得
- `WindowFromPoint`, `ChildWindowFromPoint` - ウィンドウ検出
- `GetWindowRect`, `GetWindowText` - ウィンドウ情報取得
- `SetForegroundWindow`, `SetWindowPos` - ウィンドウ操作
- `RegisterHotKey`, `UnregisterHotKey` - ホットキー登録
- `GetDeviceCaps` - デバイス情報取得
- `SystemParametersInfo` - システム設定
- `SHGetSpecialFolderLocation` - シェルフォルダ取得

**C#での対応:**
```csharp
// P/Invokeを使用
[DllImport("user32.dll")]
static extern bool BitBlt(IntPtr hObject, int nXDest, int nYDest,
    int nWidth, int nHeight, IntPtr hObjectSource,
    int nXSrc, int nYSrc, int dwRop);

[DllImport("gdi32.dll")]
static extern bool StretchBlt(IntPtr hdcDest, int nXOriginDest,
    int nYOriginDest, int nWidthDest, int nHeightDest,
    IntPtr hdcSrc, int nXOriginSrc, int nYOriginSrc,
    int nWidthSrc, int nHeightSrc, int dwRop);
```

**評価**: P/Invokeで実装可能。型のマッピングに注意が必要。

#### 2.2.2 ビットマップ処理
**Delphiの特徴:**
- `TBitmap` クラス
- `Canvas.Handle` によるGDIハンドル直接アクセス
- `ScanLine` によるピクセル直接アクセス
- `PixelFormat` (pf1bit, pf4bit, pf8bit, pf15bit, pf16bit, pf24bit, pf32bit)

**C#での対応:**
- `System.Drawing.Bitmap` クラス
- `Graphics.FromImage()` による描画
- `LockBits()` / `UnlockBits()` によるピクセル直接アクセス
- `PixelFormat` 列挙型（対応あり）

**注意点:**
- `ScanLine` の直接アクセスは `LockBits()` で代替
- メモリレイアウトの違いに注意（BGR vs RGB）
- パフォーマンステストが必要

**変換例:**
```csharp
// Delphi
var scanLine = bitmap.ScanLine[y];
var pixel = PRGBArray(scanLine)^[x];

// C#
var bitmapData = bitmap.LockBits(
    new Rectangle(0, 0, bitmap.Width, bitmap.Height),
    ImageLockMode.ReadWrite, bitmap.PixelFormat);
try {
    unsafe {
        byte* ptr = (byte*)bitmapData.Scan0;
        int offset = y * bitmapData.Stride + x * 3;
        // BGR順序に注意
    }
} finally {
    bitmap.UnlockBits(bitmapData);
}
```

#### 2.2.3 画像回転処理 (`XRotateBitmap.pas`)
**特徴:**
- 任意角度の回転（10度単位）
- 複数のピクセルフォーマット対応
- 低レベルなピクセル操作

**C#での対応:**
- `System.Drawing.Graphics.Transform` を使用（簡単だが品質に課題）
- または、`LockBits()` でピクセル単位処理（Delphiコードと同様）
- または、`System.Drawing.Imaging.ImageAttributes` と `Matrix` を使用

**評価**: 実装可能だが、パフォーマンスと品質のバランスを検討が必要。

#### 2.2.4 ホットキー処理
**Delphi:**
```pascal
RegisterHotKey(Handle, Integer(MHK_ZOOMUP), MOD_CONTROL, $41);
procedure WMHotKey(var Msg: TWMHotKey); message WM_HOTKEY;
```

**C#:**
```csharp
[DllImport("user32.dll")]
static extern bool RegisterHotKey(IntPtr hWnd, int id, uint fsModifiers, uint vk);

protected override void WndProc(ref Message m) {
    const int WM_HOTKEY = 0x0312;
    if (m.Msg == WM_HOTKEY) {
        // 処理
    }
    base.WndProc(ref m);
}
```

**評価**: 実装可能。メッセージループの処理に注意。

#### 2.2.5 シェルリンク作成（スタートメニュー登録）
**Delphi:**
- `IShellLink`, `IPersistFile` (COM)

**C#:**
```csharp
using System.Runtime.InteropServices;
using IWshRuntimeLibrary; // COM参照追加

var shell = new WshShell();
var shortcut = (IWshShortcut)shell.CreateShortcut(path);
shortcut.TargetPath = exePath;
shortcut.Save();
```

**評価**: COM相互運用で実装可能。`IWshRuntimeLibrary` の参照が必要。

### 2.3 🔴 変換が困難な要素

#### 2.3.1 デバイスコンテキストの直接操作
**課題:**
- Delphiでは `Canvas.Handle` でHDCを直接取得可能
- C#では `Graphics` オブジェクト経由になる

**対応策:**
- `Graphics.GetHdc()` / `ReleaseHdc()` を使用
- または、`Graphics` クラスのメソッドで代替

#### 2.3.2 メモリ管理
**Delphi:**
- 手動メモリ管理（`GetMem`, `FreeMem`）
- 参照カウント

**C#:**
- ガベージコレクション
- `using` ステートメントまたは `IDisposable` パターン

**注意点:**
- リソースの解放タイミングが異なる
- パフォーマンス特性が変わる可能性

#### 2.3.3 文字コード
**課題:**
- Delphi: Shift-JIS (SHIFTJIS_CHARSET)
- C#: デフォルトUTF-8

**対応策:**
```csharp
Encoding.GetEncoding("shift_jis");
```

## 7. 結論

### 変換可能性: **可能**

このDelphiアプリケーションは、Visual C#への変換が可能です。ただし、以下の点に注意が必要です：

1. **Windows APIの多用**: P/Invokeの適切な実装が必要
2. **低レベルな画像処理**: `LockBits()` によるピクセル操作の実装が必要
3. **パフォーマンス**: リアルタイム処理の最適化が必要
4. **作業量**: 3,000行超のコード変換には相当な時間が必要

### 推奨事項

1. **段階的変換**: 機能ごとに分割して実装
2. **テスト重視**: 各機能の動作確認を徹底
3. **パフォーマンス測定**: 変換前後で比較
4. **ドキュメント化**: P/Invoke定義などを文書化
