# 不具合報告テンプレート

## 目的

StretchViewCS の不具合を、再現可能で修正判断しやすい形で記録するためのテンプレートを残す。

特に本プロジェクトは `WinForms`、`Win32 API`、画面キャプチャ、ホットキー、入力注入など環境依存が強いため、曖昧な報告では原因追跡が難しい。

## 使い方

- 不具合 1 件につき、このテンプレートを 1 つコピーして記録する
- 再現しない推測や感想だけで終わらせず、再現条件を必ず書く
- 画面系の問題は、操作前後の状態差が分かるように書く
- 再現頻度が低い場合でも、試行回数を記録する

## 記入例

```md
# 不具合報告

## 基本情報

- 報告日: 2026-04-12
- 報告者: 開発者A
- 確認環境: Windows 11
- Visual Studio バージョン: 2022 17.x
- ビルド構成: Debug|Any CPU
- 対象ブランチ: main
- 対象コミット: abcdef1

## 不具合の要約

- 概要: 固定表示を有効化した直後に、表示位置が左上へ大きくずれる
- 期待結果: 選択した範囲の中心を維持して固定表示へ移行する
- 実際の結果: 表示領域がデスクトップ左上付近へ飛ぶ

## 発生箇所

- 対象画面: メイン画面
- 対象機能: 固定表示
- 関連ファイル候補: frmCap.cs

## 再現手順

1. アプリを起動する
2. 固定表示メニューから範囲指定を開始する
3. 画面右下付近をドラッグして確定する

## 再現率

- 高頻度
- 試行回数: 5
- 発生回数: 4

## 発生条件

- 起動直後か: はい
- 設定変更後か: いいえ
- 最小化、復元後か: いいえ
- 他アプリと同時使用か: はい
- マルチモニタ環境か: いいえ

## エラーメッセージ

- ダイアログ表示: なし
- Output ウィンドウ: 特になし
- 例外内容: 未確認

## 画面観察

- 表示崩れ: あり
- フリーズ: なし
- 高CPU使用: なし
- 操作不能: なし

## 影響範囲

- 他機能への影響: 固定表示中の位置調整が困難
- 回避手段の有無: 何度かやり直すと成功することがある
- 作業継続可否: 継続は可能

## 補足

- 関連しそうな変更: 固定表示オーバーレイ導入後から発生
- 直前に行った操作: なし
- 添付画像、動画、ログ: あり
```

## 報告時に最低限ほしい情報

- 再現手順
- 期待結果と実際の結果
- 発生頻度
- 使用環境
- 例外やエラーメッセージの有無

## よくある不足情報

- どの画面で起きたか不明
- 何回試して何回起きたか不明
- Debug か Release か不明
- Visual Studio 起動か単体 exe 起動か不明
- 直前の設定変更や操作が不明

## 推奨運用

- 不具合確認時は [Windows版VisualStudio確認チェックリスト.md](/C:/repos/StretchViewCS/docs/Windows版VisualStudio確認チェックリスト.md) とセットで使う
- 再現したらその場で記録し、記憶で後から埋めない
- 修正後は同じ報告テンプレートを使って再確認結果を追記する
